1. **Own-hold realtime race (critical):** after `createSeatHold` succeeds, Supabase may emit `DANG_GIU` for those same selected seats. The current realtime callback blindly calls `reconcileSelectionAfterUpdate`, removes them from `selectedSeats`, and makes the successful hold dialog show 0 seats / 0 total. Preserve a stable held-seat snapshot and ignore/reconcile own-hold `DANG_GIU` updates correctly while still removing seats lost to another actor before hold success. Avoid stale closures; use a ref or a pure helper with tests.
2. **Release truthfulness (critical):** `handleReleaseHold` clears local hold state and announces success in `finally`, even when `releaseSeatHold` fails. On failure, keep the active hold/countdown and show an actionable error. Only clear state and announce success after confirmed release.
3. **409 conflict stale selection (critical):** after refreshing catalog, the current selection still contains stale seat objects. Reconcile selection against the refreshed catalog, remove unavailable seats, and identify affected seat codes. Do not permit a second hold request with stale selections. Make catalog loading return data or use a pure reconciliation helper with tests.
4. **Event/show boundary (high):** a route/show change can leave selection, inspected seat, banner, active hold, and in-flight catalog result from the previous event in the mounted component. Add a race-safe event/show scope reset. Do not let an old async response overwrite a newer scope. If an active hold cannot be safely persisted across scope changes, attempt release and clearly document the behavior; do not silently display it under another event.
5. **No-zone state (high):** `loadTicketingCatalog` throws when Supabase returns zero zones, so the new UI renders a connection error rather than the intended empty/not-applicable state for organizer events without reserved seating. Return an empty catalog for zero zones; reserve `error` for actual failures.
